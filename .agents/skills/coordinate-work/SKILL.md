# 작업 조정

## 입력과 출력
입력: 목표·자료·요구사항, 도구 접근, 실행 예산. 출력: run 설정, 의존 작업표, 중간 산출물, 체크포인트, 최종 검증 보고.

## 절차
1. 새 작업이면 interview-requirements로 목표/성공 기준을 정의하고 prepare-evidence로 자료를 확인한다.
2. [실행 계약](references/run-contract.md)에 따라 설정과 `work/RUN-ID/state.json`을 만든다. 시간·재시도·동시 실행 수를 시작 전에 확인한다. 이 Skill은 에이전트의 운영 절차이며 별도 자동 스케줄러가 아니다.
3. 작업마다 입력, 출력 경로, 의존성, 담당 Skill, 완료 조건을 둔다. OCR/미디어/브라우저 추출을 최종 추론과 분리한다. 각 추출은 원본 위치와 불확실성을 함께 출력한다.
4. 독립 입력과 독립 출력 경로를 가진 작업만 병렬 처리한다. 세션/캐시/lockfile을 공유하는 도구는 직렬화한다. 서브에이전트는 현재 환경/사용자 권한이 허용할 때만 사용한다.
5. 각 작업 전 deadline/남은 시간/횟수를 확인하고 외부 명령 timeout을 남은 시간 이하로 설정한다. 실패 시 원인과 시도한 변경을 기록한다. 같은 접근에 진전이 없으면 반복하지 않는다.
6. 단계마다 state를 임시 파일에 쓴 뒤 원자적으로 교체한다. 재개 시 출력 파일 존재·해시·입력 해시·설정 버전을 확인하여 stale 결과를 재사용하지 않는다.
7. 자료를 종합해 해결안을 만들고 예외/반례를 점검한다. 에이전트 제작이면 입력/출력 계약과 도구 실패·질문 응답, 평가 케이스를 함께 전달한다.
8. 마지막 작업은 반드시 verify-results다. 요구사항별 pass/fail/unverified와 남은 설정을 보고한다. 자동 제출/게시 권한을 이 Skill이 부여하지 않는다.

## 실패 전환 및 완료
횟수·시간 초과 또는 설정된 무진전 한도에 도달하면 원인/영향/다른 접근을 기록하고 대체 도구나 사람 검토로 전환한다. 재개 가능한 산출물과 최종 검증 보고가 있고 누락·미검증이 드러나면 조정 완료다. 성공 기준 미달이면 해결 성공으로 표시하지 않는다.
