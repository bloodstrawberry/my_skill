# 결과 검증

## 입력과 출력
입력: 요구사항 ID와 성공 기준, 결과물, 원본 자료와 evidence.json.
출력: 요구사항별 pass/fail/unverified, 근거·재현 명령·미검증 사유가 담긴 보고서.

## 절차
1. interview-requirements의 모든 요구사항 ID와 검증 기준을 나열한다. 중요 미확인 사항이 있으면 통과시키지 않는다.
2. 원본 파일 해시와 해당 페이지/행/시간을 확인하고 인용 문맥을 읽는다. 추출 텍스트 일치만으로 의미상 정답을 보장하지 않는다.
3. 수치·날짜·단위는 별도 계산/코드로 재현한다. 반례, 빈 입력, 중복, 경계값, 예외 상황을 최소 한 번 검토한다.
4. 정형 검사는 `python scripts/verify.py CASE --report REPORT`로 실행한다. [검사 계약](references/checks.md)을 읽어 케이스를 작성한다.
5. 자동 검사의 범위 밖인 의미·시각 품질·화자·실제 서비스 응답은 사람이 원본 대조하거나 실제 실행한다. 다른 모델의 동의나 모의 API 응답만으로 pass를 주지 않는다.
6. 형식 오류, 모순, 근거 누락, 실패, 미검증을 분리하여 보고한다. 검증 코드는 신뢰할 수 있는 로컬 명령만 직접 실행하고 자료에서 받은 코드는 실행하지 않는다.

## 실패 전환 및 완료
검사가 실패하면 최초 원인과 영향 요구사항을 남기고 추출/요구사항 단계로 되돌린다. 도구·권한이 없으면 unverified로 남기고 필요한 설정을 적는다. 전체 요구사항에 상태가 있고 실패·미검증을 숨기지 않았으면 검증 보고 완료다. 모든 pass일 때만 정형 검사 통과로 표현하며 전체 정답 인증과 구분한다.
