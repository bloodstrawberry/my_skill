# write-deliverables

## 실행 환경
Cofa 응시에서는 docs/hackathon.md와 AGENTS.md의 대회 제한을 먼저 적용한다. 외부 API/추가 AI 모델은 실행하지 않는다. 다른 대회와 일반 연습은 해당 환경의 허용 범위를 확인한다.

## 입력·출력
입력: 과제 README, 요구사항, 실제 구현/테스트 로그. 출력: 요구된 파일명·형식의 문서와 출처 목록.
## 절차
1. 실제 과제의 제출 계약을 읽고 필수 파일/경로를 추출한다. 이 저장소 예제를 공식 양식으로 오해하지 않는다.
2. 문제 정의, 선택한 해결책, 사용법, 실행 명령, 검증, 한계를 실제 작업 근거로 작성한다.
3. decision-log.md에 결정·대안·선택 이유·근거·변경 영향을 남긴다. 외부 자료는 URL/버전/차용 범위를 기록한다.
4. Markdown을 기본으로 하고 DOCX 요구가 있으면 python-docx로 만들고 다시 열어 문단/표를 점검한다. PDF 요구는 pdf Skill로 렌더링 검토한다.
5. 테스트하지 않은 기능을 완료로 쓰지 않는다. 사용자에게 구현을 설명할 수 있도록 결정과 검증 위치를 연결한다.
6. verify-results로 필수 파일·명령 재현·요구사항 대응을 점검한다. 제출 확정과 업로드 완료를 구분한다.
## 실패·완료
변환 도구가 없으면 허용된 형식 여부를 확인하고 미검증을 보고한다. 제출 계약과 실제 구현이 일치하고 근거·한계가 명시되면 완료한다. Cofa 후속 서술형 단계에서는 AI로 답안을 작성하지 않는다.
## 도구 근거
https://python-docx.readthedocs.io/en/latest/ . 자체 작성 지침이다.
